# 安全与副作用边界

## 默认允许

- 读取项目源码、文档和已有测试。
- 编写脚本、文档、模拟装置和回归测试。
- 运行语法检查、kit 测试和明确无真实业务副作用的模拟测试。
- 在用户指定的运行目录内读取 run.log、失败截图和 trace 进行分析。

## 必须得到明确许可

以下操作不能因为是“测试”就默认执行：

- 真实删除、提交、支付、修改资料、批量写入或任何不可逆业务动作。
- 调用真实上报接口、真实企微 Webhook 或发送真实通知。
- 对生产账号执行点击、表单提交、Cookie 修改、清理 Cookie。
- 覆盖安装、卸载、结束应用/浏览器进程、部署到真实实例环境。
- 复制、迁移或删除实例 profile、用户 Excel、运行记录等数据。
- 在项目工作目录之外扫描或修改文件；用户明确指定目标文件/目录的读取除外。

许可应具体到动作和环境。用户允许“只读查看页面”不代表允许点击按钮；允许“测试一条”不代表允许批量执行。

## 数据处理

- 不打印或提交密码、Cookie、Token、完整 Webhook key、身份证/手机号等敏感信息。
- 网络监听默认不开启 Header/Body；确需采集时限制 URL 和大小，并避免记录认证信息。
- 不把真实 profile、运行产物、用户 Excel 或 HAR 中的敏感数据复制进源码包。
- `removeCookies()` 不传筛选条件会清空上下文全部 Cookie，默认禁止。
- 多实例共享 `dataDir` 有文件冲突风险，默认使用 `instanceDir`。

## 修改纪律

- 不执行 git commit/push/reset/rebase 等变更，除非用户明确要求并再次确认。
- 不通过删除日期筛选、账号校验、最大数量限制等安全条件来让脚本继续运行。
- 不用 DOM 点击成功代替业务成功；涉及真实写入时必须核实结果。
- 不把手动停止误报为任务失败。
- 部署工具会写安装版和测试环境并修改防回滚指纹，运行前必须确认目标。

## 调试工具

`tools/dom-spy.mjs` 默认带历史业务环境配置，使用前必须显式设置：

- `RPA_DATA_DIR`
- `RPA_INSTANCE`
- `RPA_URL`

优先只用 `snapshot/find/sel/point/text` 等只读命令。`click` 会改变页面状态，必须单独取得许可。即使只读采集也会启动实例并可能导航页面，使用前应说明目标环境。
